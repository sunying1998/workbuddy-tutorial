选择并验证 Skill / 专家

同一个任务，可以用三种方式做：普通指令、Skill、专家。官方把它们的定位写得很清楚：

维度Skill专家（Agent 型）专家团（Team 型）
组成关系工具能力：让 AI 能做某件事AI 顾问：懂某个领域的 AI 角色AI 协作团队：自动拆解、并行执行、完整交付
怎么选需要 AI 具备某种工具能力有一个明确的单点问题任务复杂，需要多角色配合
Skill 是能力；专家是能力 + 经验；专家团是多位专家 + 协作流程。
它们不是互斥的三个选项：用专家的时候照样可以让它调用 Skill。本讲要判断的是"这个任务，哪种组合最省事"。
准备材料

一个小任务，三种方式各做一次

材料说明
一个小任务建议用「给复盘报告配一张流程图」——小、可重复、能对比

一个专家入口：左侧边栏点击「专家」 → 专家中心按行业分类浏览 → 召唤

照着做

五步：定验收 → 三次对比 → 记录卡 → 只读检查 → 确认后安装

  1. 先明确这个小任务的验收标准
    例如：能生成一张包含"报名 → 反馈 → 报告"三个环节的流程图；文字用中文；能拿到可看的成品。不然后面比不出差别。
  2. 三种方式各做一次，同一份输入、同一个验收标准
    重点是记录各自解决了什么、额外付出了什么：
    方式它额外解决了什么你额外付出了什么
    普通指令（做完填）（做完填）
    Skill
    专家
    （可选）专家 + Skill
  3. 填能力选择记录卡（本讲核心产出）
    维度普通指令Skill专家
    它解决了什么
    我额外付出了什么（准备 / 安装 / 学它的说法）
    产出能否达到验收标准
    换一批数据再做，还省事吗
    下次同类任务我会怎么组合
  4. 安装前的只读检查（安全动作，不能跳）
    官方原文：非官方 Skill 可能存在恶意提示词注入、越权访问、后门程序等隐患，请优先使用官方推荐 Skill；安装第三方 Skill 前，请仔细查看其权限申请、来源说明与脚本内容，确认数据外发范围与可信度。
    请先做只读检查，不要安装。给我这个技能的以下信息：①它来自哪里、由谁维护、最近有没有更新；②它会读写我本地的哪些文件和目录；③里面有没有脚本、脚本具体会做什么；④有没有联网、对外发送、或调用外部服务的操作。我确认之后你再安装。
  5. 你确认后再安装 —— 安装有三条官方路径
    路径官方说明什么时候用
    上传技能导入本地技能包：拖拽或点"选择文件"，导入后自动完成配置你已经拿到技能文件
    查找技能输入任务描述，自动查找相关技能知道要干什么、不知道有没有现成技能
    创建技能输入任务描述，自动创建技能找不到合适的，让 AI 造一个
    另外两个官方概念要分清：关闭 ≠ 卸载 —— 关闭只是暂停模型自动调用，技能仍保留在已安装列表；卸载才彻底删除。官方建议只启用当前任务需要的技能。
中途检查

四条检查 + 三条专家事实

检查项通过标准
对比是否公平三次用的是同一份输入、同一个验收标准
是否记录了失败有失败也要写进卡片，不能只记成功的
是否写清触发方式至少要能写出"下次我这么说就会调用它"
安装前检查是只读检查（来源 / 读写范围 / 是否含脚本 / 是否联网或对外发送），且你确认之后才安装

关于专家的三条官方事实（讲评时可用）

  1. 专家不主动获取系统权限
    它只处理你主动提供的对话与上传文件；只有配备 Skill / MCP 时才在你的授权下间接访问。
  2. 专家团更贵，也更麻烦
    会并行调用多位专家，消耗通常是单专家的 3–5 倍；且在专家团会话里切换其他专家需要开启新对话。
  3. 官方免责
    专家生成内容仅供参考，不构成专业意见。
预期结果

一张记录卡 + 一句结论

学员可见：一张填满的记录卡（含"它解决了什么 / 我额外付出了什么"两栏）+ 一句明确结论："这个任务，我以后用【哪种组合】，因为……"

展开对照材料（注意：这里不给"哪种方式更好"的结论）
  • 三种方式各自解决了什么：普通指令 = 这次就干这一件事，零准备；Skill = 这类活有成熟做法、产物要一致，代价是安装与触发方式学习；专家 = 需要某类专业判断和固定工作方法，代价是按它的方式沟通；组合 = 在专业角色下复用打包好的能力，常见且合法。
  • 要付出什么：安装检查的时间、记触发词的成本、失败时的回退成本。
  • 判断依据不是"哪个更高级"，而是：这个任务以后还会不会重复、需不需要产物一致、需不需要专业判断。
  • 失败退路的写法示例："若 Skill 装不上或产物不符合验收标准，回退为普通指令 + 手工调整流程图。"
  • 学员的结论只要论证站得住就算对——例如"这次只用普通指令就够，因为它只做一次"，也是合格答案。

独立练习

只改一个条件

换一个新技能，完整走一遍：只读检查 → 你确认 → 安装 → 测试输入 → 记录 → 写出触发例句。

展开参考答案（做完再看）
  1. 卡片五项（来源 / 读写范围 / 脚本 / 对外操作 / 失败退路）缺一不可；
  2. 触发例句必须自己试出来，不能照抄说明文档 —— 说明文档的触发词在中文对话里不一定生效；
  3. 若测试产物不符合验收标准，正确结论是"这次不合适"并写清退路，而不是"再试几次"；
  4. "只读检查"与"安装"必须是两步：检查完由你确认，再安装。
